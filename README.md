# CS 350: Emerging Systems Architectures and Technologies

## Portfolio Reflection

### Summarize the project and what problem it was solving.

For my CS 350 portfolio, I selected my Morse Code state machine project and my final thermostat project. The Morse Code project used a Raspberry Pi, LEDs, and a button to create a state machine that displayed different Morse Code messages. The thermostat project expanded on the skills I learned throughout the course by using buttons, LEDs, an LCD display, and a temperature sensor to create a functioning thermostat. The system could switch between off, heating, and cooling modes, adjust the set temperature, and respond to the current temperature.

### What did you do particularly well?

I did particularly well with debugging and getting the different hardware and software components to work together. Throughout these projects, I had to troubleshoot wiring, GPIO connections, code, and hardware behavior to determine why the system was not working as expected. I also did well implementing state machines to control the behavior of both projects and organizing the different inputs and outputs.

### Where could you improve?

One area I could improve is providing more detailed examples in my technical documentation. For example, I could include an exact example of the UART output from the thermostat and provide a more detailed explanation of how the system could communicate with a cloud platform. I could also continue improving my ability to troubleshoot hardware problems efficiently as I gain more experience working with embedded systems.

### What tools and/or resources are you adding to your support network?

This course gave me experience using a Raspberry Pi, Python, GPIO, I2C, UART, sensors, LEDs, buttons, and LCD displays. I also learned how useful hardware documentation, component diagrams, and technical documentation can be when troubleshooting an embedded system. These resources will be useful references if I work with embedded systems or hardware and software integration again.

### What skills from this project will be particularly transferable to other projects and/or coursework?

The most transferable skill from these projects is debugging. I learned to break a problem into smaller pieces and test the hardware, wiring, and software individually instead of assuming the problem was coming from one specific area. The experience I gained using Python, state machines, hardware interfaces, and technical documentation will also transfer to future software development projects.

### How did you make this project maintainable, readable, and adaptable?

I made my code maintainable and readable by separating different responsibilities into functions and using descriptive names for states, callbacks, and hardware behavior. Using state machines also helped organize the program logic so that each state had clearly defined behavior and transitions. This structure makes the projects easier to understand, troubleshoot, and modify if additional hardware or functionality is added in the future.
